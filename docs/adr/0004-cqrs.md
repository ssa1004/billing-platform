# ADR-0004: CQRS — JPA 쓰기, 분리가 필요한 곳만 별도 읽기

## 상태
적용

## 배경
write 모델은 도메인 invariant 를 강제 → JPA aggregate root + Hibernate dirty checking 이 적합. 그런데 read 모델은 *"내 거래 내역 30건 + 합계 + 페이징"* 같은 형태 — JPA 로 짜면 N+1 또는 fetch join 으로 무거워짐. 반대로 read 모델의 SQL 을 JPA 로 짜는 건 항상 어색하고 비효율.

## 결정
**CQRS** — Write 는 JPA (aggregate 단위 dirty checking), Read 는 JOOQ-style native SQL (DTO projection). 다만 **read divergence 가 실제로 생기는 곳만** 분리. 단순 단건 조회는 JPA 그대로.

본 v0.1 에선 read 가 단순해 JpaRepository 로 처리 — read 모델이 복잡해지면 `wallet-adapter-out/persistence/jooq/` 에 JOOQ 또는 JdbcTemplate 기반 reader 추가.

## 결과
- write 는 도메인 invariant + 낙관적 락이 자연스러움
- read 가 단순한 동안엔 over-engineering 회피 (성숙도에 따라 분리)
- 향후 분리 시 application 의 query port 만 변경 → controller 영향 없음
- (단점) 분리 후엔 read model 동기화 별도 (Outbox event 컨슈머가 read table 갱신)
