# ADR-0004: CQRS — JPA 쓰기, 분리가 필요한 곳만 별도 읽기

## 상태
적용

## 배경
쓰기 모델은 도메인 invariant (항상 만족해야 하는 도메인 규칙) 를 강제하기에 좋아서 JPA
aggregate root + Hibernate 의 dirty checking (변경된 필드만 감지해서 자동 UPDATE) 이
적합합니다. 그런데 읽기 모델은 "내 거래 내역 30건 + 합계 + 페이징" 같은 형태로,
JPA 로 짜면 N+1 (한 쿼리에 추가 쿼리 N번 따라붙는 흔한 성능 문제) 또는 fetch join 으로
무거워집니다. 반대로 읽기용 SQL 을 JPA 로 짜는 건 항상 어색하고 비효율적입니다.

## 결정
**CQRS** (Command Query Responsibility Segregation, 쓰기와 읽기 모델을 분리하는 패턴) —
쓰기는 JPA (aggregate 단위 dirty checking), 읽기는 JOOQ 스타일 native SQL (DTO projection,
필요한 컬럼만 DTO 로 매핑). 다만 **읽기 모델이 실제로 분리되어야 하는 곳만** 분리합니다.
단순 단건 조회는 JPA 그대로 둡니다.

본 v0.1 에서는 읽기 모델이 단순해 JpaRepository 로 처리합니다. 읽기 모델이 복잡해지면
`billing-adapter-out/persistence/jooq/` 에 JOOQ 또는 JdbcTemplate 기반 reader 를 추가합니다.

## 결과
- 쓰기는 도메인 invariant + 낙관적 락 (충돌 시 예외 후 재시도) 이 자연스러움
- 읽기가 단순한 동안엔 과도한 추상화 (over-engineering) 회피 (성숙도에 따라 분리)
- 향후 분리 시 application 의 query port 만 바꾸면 됨 → 컨트롤러는 영향 없음
- (단점) 분리 후엔 read model 동기화가 별도 작업 (Outbox 이벤트 컨슈머가 read 테이블 갱신)
