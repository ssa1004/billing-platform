# ADR-0001: Spring Modulith 기반 모듈러 모놀리스 (MSA 대신)

## 상태
적용

## 배경
초기 결제 시스템에 MSA (마이크로서비스 아키텍처, 도메인별로 별도 서비스/배포 단위로 쪼개는
구조) 도입을 검토했습니다. 한 팀(10명 미만) 규모에서는 마이크로서비스의 운영 비용 — 여러
서비스에 걸친 분산 트랜잭션, 서비스 메시 (서비스 간 호출을 중계/관찰하는 인프라),
서비스마다 별도의 배포 파이프라인 — 이 너무 큽니다. 그렇다고 단일 클래스 / 단일 패키지로
이뤄진 거대한 monolith (한 덩어리) 도 변경 영향 분석이 어렵습니다.

## 결정
**모듈러 모놀리스** + Spring Modulith. 하나의 Spring Boot 앱 안에 도메인별 모듈
(wallet/order/payment/refund/ledger) 을 두고, Spring Modulith 가 컴파일 외에도 모듈 사이의
의존 그래프를 검증 (verify) 합니다.

## 결과
- 운영 단순 (배포 한 번, DB 트랜잭션 하나)
- 모듈 경계 위반은 빌드 실패 (`ApplicationModules.verify()`)
- 향후 특정 모듈만 떼어내 MSA 로 전환 가능 (이미 의존 방향이 정리되어 있음)
- (단점) 한 모듈에서 OutOfMemory 가 발생하면 앱 전체가 영향을 받음
- (단점) 팀별 독립 배포 불가 (한 팀 규모에선 오히려 장점)
